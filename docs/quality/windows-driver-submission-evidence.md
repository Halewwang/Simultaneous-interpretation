# Windows Driver Submission Evidence

The Windows Audio workflow produces one portal-ready, unsigned driver archive
for the EMKE virtual-audio package. The archive contains exactly:

- `EMKE.VirtualAudio.inf`
- `EMKE.VirtualAudio.sys`
- `EMKE.VirtualAudio.cat`
- `driver-submission.json`

The package inventory inside `driver-submission.json` is limited to the INF,
SYS, and CAT. Each entry records a lowercase SHA-256 hash calculated again from
the copied destination bytes. The manifest also freezes source commit, driver
version `1.0.0.2`, ABI `1`, Windows build floor `19045`, and KMDF `1.31`.

`windows-driver-submission.zip` is deterministic: entry order, entry paths,
compression mode, and the ZIP timestamp are fixed. The sibling runtime file
`driver-submission-evidence.json` records the workflow run ID, source commit,
pinned WDK package version, archive SHA-256, and the three package hashes. The
runtime evidence is outside the ZIP so CI-specific values do not change the
portal-ready package.

The hosted workflow contains no test certificate, PFX, private key, or signing
secret. Its CAT is generated by Inf2Cat and is unsigned. Submission to
Microsoft Hardware Dev Center, Attestation or WHQL processing, download of the
Microsoft-signed result, kernel-policy validation, installation, Secure Boot
acceptance, endpoint validation, and release approval are external gates
outside this build workflow.
