## 1. 设计目标

将当前“所有配置同时展开”的原生 SwiftUI 工具面板改造成会议中可一眼确认的翻译控制台。主面板必须让用户在三秒内回答四个问题：

1. 翻译是否正在运行；
2. 我听到的语言方向是什么；
3. 对方听到的语言方向是什么；
4. 当前是否存在旁路、静音或连接异常。

用户开始或停止翻译只需要一个主动作。API、模型和物理设备配置进入二级设置视图，不与运行状态争夺注意力。

## 2. 视觉语言

本设计参考 Typeless 的视觉原则，不复制其品牌、文案、Logo、素材或网页布局。

- 使用黑、白和语义灰建立主要层级；蓝色只作为极弱的实时音频活动提示。
- 依靠字号、字重、对齐、留白和细分隔线组织内容，不堆叠卡片。
- 同一屏只保留一个深色胶囊主按钮。
- 优先使用 SF Pro 与 SF Symbols，保持 macOS 原生可读性，不引入网页字体依赖。
- 主面板以 420 × 620 pt 为设计基准，内容必须在该尺寸内完整显示，不依赖主界面滚动。
- 使用语义系统颜色适配浅色与深色模式；浅色模式是已确认视觉稿的主基准。

### 2.1 设计令牌

| 令牌 | 合同 |
| --- | --- |
| 水平边距 | 左 22 pt、右 24 pt，以匹配已确认视觉稿 |
| 基础间距 | 8 pt；组合间距使用 16、24、32 pt |
| 顶栏标题 | 13 pt，semibold |
| 语言值 | 22 pt，semibold |
| 通道标题 | 17 pt，semibold |

| 面板圆角 | 由 `MenuBarExtra(.window)` 系统容器提供，不在内容中重复造大卡片 |
| 动效帧率 | 最高 30 fps |

## 3. 信息架构

菜单栏应用只包含两个应用内层级：

1. **翻译控制台**：默认入口，承载运行状态、语言方向、双通道、旁路与启停。
2. **设置**：由右上角齿轮进入，承载服务商、模型、Keychain 凭据和物理设备。

设置返回控制台时不得重新创建正在运行的 Translation 会话。翻译运行期间会锁定会改变会话或设备的设置，但允许查看当前值。

## 4. 翻译控制台

从上到下固定为六个区域。

### 4.1 顶栏

- 左侧显示 `EMKE Translation`。
- 右侧使用 SF Symbol `gearshape` 进入设置。
- 顶栏不重复显示连接状态；状态由音波区和通道区表达。

### 4.2 实时音波主视觉

- 音波是运行状态的第一视觉焦点，取代大号静态“翻译中”。
- 音波由 24 个垂直胶囊条组成，使用黑色、石墨灰和一个极弱的冷蓝活动端点。
- 音波下方始终显示可读文字：`翻译中 · mm:ss`、`正在连接`、`准备开始` 或明确错误状态。
- 运行时主音波使用入站和出站归一化电平的较大值，表达“翻译活动”；方向差异由下方两个通道的小音波负责。
- 静音时胶囊条回落到低幅静态基线，不使用持续假随机动画。

#### 音波数据与动画

- 音频电平在本机从现有 24 kHz mono PCM16 块计算 RMS，不把音频或电平写入磁盘。
- 入站与出站分别产生 `0...1` 的归一化电平；UI 以不高于 30 Hz 的频率接收快照。
- 动画采用快速起音、缓慢释放：目标起音约 80 ms，释放约 220 ms，避免语音停顿时闪烁。
- 24 个柱形由最近的平滑电平和固定权重生成，不能使用每帧随机数，因此相同输入应产生可测试的确定性结果。
- 主音波取两路电平较大值；通道小音波只使用对应通道电平。
- 当系统开启“减弱动态效果”时，关闭逐帧插值，显示静态音波轮廓与文字状态。
- 当窗口不可见或翻译停止时，动画计时器必须停止。

### 4.3 语言方向

- 左侧为“我的母语”，右侧为“会议输出”，中间使用右箭头。
- 可见语言名使用本地化中文“中文／英语／德语”；持久化与协议 raw value 继续使用 `zh/en/de`。
- 就绪状态可直接选择语言；运行期间显示当前语言并锁定选择器。
- 该区域只表达用户配置方向，不替代两个通道的真实流向标签。

### 4.4 双通道

两个通道使用行式布局，以细分隔线区分，不放入独立卡片。

**我听到**

- 图标：`headphones`。
- 方向：例如 `德语 → 中文`。
- 状态：稳定、连接中、播放原音、重连中或失败。
- 右侧动作：正常时为“播放原音”；旁路后为“恢复翻译”。
- 小音波只反映入站会议音频活动。
- 在服务商尚未给出可验证的入站语种时显示“其他语言 → 中文”，不得为匹配示意稿而伪造为具体语种。

**对方听到**

- 图标：`mic`。
- 方向：例如 `中文 → 德语`。
- 状态：稳定、连接中、已静音、发送原音、重连中或失败。
- 右侧动作：正常时为“发送原音”；旁路后为“恢复翻译”。
- 小音波只反映真实麦克风活动。

旁路状态必须同时通过文字与图标表达，不能只改变颜色。出站连接失败时保持 fail-closed，并明确显示“已静音”；不得用正常音波掩盖该状态。

### 4.5 主动作

- 就绪：`开始翻译`。
- 启动中：按钮保留尺寸，显示进度并禁用重复触发。
- 运行中：`停止翻译`。
- 缺少必要配置：按钮禁用，音波下的状态文字指出第一个需要修复的项目。
- 危险状态不弹出额外确认；停止操作必须立即可达。

### 4.6 隐私提示

底部固定显示 `音频直连你的服务商`，配合 `lock` SF Symbol。该文案只说明网络拓扑，不暗示第三方服务商零留存。

## 5. 设置视图

设置使用单层分组列表，不使用多级导航。

### 5.1 服务商

- API Key：安全输入，已保存时只显示“已存入 Keychain”，永不回填明文。
- Base URL。
- Model ID。
- `测试连接` 按钮和结构化结果摘要。
- 测试只完成协议握手时必须显示“协议通过，需要音频测试”，不能显示“完全兼容”。

### 5.2 音频设备

- 真实麦克风。
- 真实耳机／扬声器。
- 刷新设备。
- 虚拟驱动缺失时显示明确修复说明。

### 5.3 设置行为

- 左上角返回控制台，右上角不再重复提供“完成”。
- 公开设置持续写入 UserDefaults，API Key 只写入 Keychain。
- 设置错误就地显示在对应分组下，不把长错误字符串推到主控制台。

## 6. 状态映射

| 运行状态 | 主音波 | 主文字 | 通道行为 |
| --- | --- | --- | --- |
| 未配置 | 静态低幅灰色 | 指出缺失配置 | 显示设备／服务缺失 |
| 就绪 | 静态低幅黑灰 | 准备开始 | 两路已就绪 |
| 连接中 | 低速确定性呼吸 | 正在连接 | 分别显示连接中 |
| 翻译中 | 真实电平驱动 | 翻译中 · 时长 | 两路独立音波与稳定状态 |
| 入站失败 | 主音波仍可反映原音 | 入站播放原音 | 入站 fail-open，出站保持原状态 |
| 出站失败 | 不显示虚假出站活动 | 出站已静音 | 出站 fail-closed，入站保持原状态 |
| 手动旁路 | 对应通道音波可继续显示原音电平 | 显示原音旁路 | 动作变为恢复翻译 |
| 停止中 | 音波回落 | 正在停止 | 禁用重复操作，等待尾音排空 |

错误色仅作为辅助：警告使用系统橙色，阻断性错误使用系统红色；所有状态必须有文字和符号冗余。

## 7. SwiftUI 组件边界

现有单文件界面拆分为以下小组件：

- `MenuBarRootView`：控制控制台／设置两种界面模式。
- `TranslationDashboardView`：布局主控制台，不访问 Keychain 或音频引擎。
- `TranslationSettingsView`：编辑公开配置和 API Key 草稿。
- `LiveWaveformView`：只接收归一化电平、运行状态与 Reduce Motion 环境值。
- `TranslationChannelRow`：显示单个方向、状态、音波和旁路动作。
- `EMKEVisualStyle`：集中管理间距、字号和语义颜色。

`MenuBarModel` 继续拥有用户动作和状态编排，但增加：

- 已运行时长；
- 入站／出站归一化电平；
- 当前界面模式；
- 适合 UI 显示的结构化错误，不暴露原始凭据或 Authorization 内容。

音频电平通过有界、可丢弃的状态快照传递。UI 消费速度慢时只保留最新快照，不能反压实时音频线程。

## 8. 可访问性

- 所有图标提供 VoiceOver 标签；音波本身标记为装饰，状态由文字读出。
- 旁路按钮的标签包含当前结果，例如“播放入站原音”和“恢复入站翻译”。
- 键盘焦点顺序：设置、语言、入站旁路、出站旁路、主动作。
- 支持 Reduce Motion、Increase Contrast 和系统字体缩放。
- 动态电平不触发高频 VoiceOver 公告；只在离散连接或旁路状态变化时公告。

## 9. 性能与安全边界

- UI 电平快照最高 30 Hz；主窗口隐藏时为 0 Hz。
- 音波绘制不得执行网络、JSON、文件 I/O 或音频复制。
- 不保存电平历史，不新增录音、字幕或分析埋点。
- 视觉改造不得改变入站 fail-open、出站 fail-closed、Keychain、双会话隔离和优雅关闭合同。

## 10. 验收标准

2026-07-18 已完成源码合同、原生交互、运行态渲染和并排视觉验收；最终结论记录于项目根目录 `design-qa.md`。当前 Command Line Tools 环境缺少 `xctrace`，因此 Instruments SwiftUI/Time Profiler trace 仍是明确的实测缺口，不把自动化性能合同写成 Instruments 通过。

Pass 5 的 canonical 证据使用浅色运行态、420 × 620 pt content、相同裁切与相同 viewport；本地验收包装器只模拟 MenuBarExtra 圆角表面、边界和阴影，不修改生产视图，也不在内容中重复增加大卡片。Pass 4 的异态证据保留为历史记录，不再支持最终结论。

- 420 × 620 pt 下主控制台无需滚动，所有关键动作可见。
- 未配置、就绪、连接中、翻译中、入站失败、出站失败、两种旁路和停止中状态均有确定性展示测试。
- 音波算法对固定 PCM 输入产生固定柱形结果；静音回落、起音和释放有单元测试。
- Reduce Motion 下不启动逐帧动画。
- 菜单栏窗口关闭后停止 UI 更新，不增加音频队列积压。
- API Key 不进入 UserDefaults、日志、截图夹具或测试失败输出。
- Swift 测试、Release 构建、菜单栏产品构建和严格 C 编译检查继续通过。
- 使用真实运行态截图与已确认视觉稿进行同尺寸比较，修复层级、间距、裁切、按钮尺寸和状态表达的 P0–P2 偏差。

## 11. 非目标

- 不复制 Typeless 品牌资产或网页动画。
- 不在本次改造中实现完整字幕历史、悬浮字幕窗或会议录音。
- 不把语速、声音角色或服务商私有声音参数混入主控制台。
- 不改变 Translation 网络协议或音频路由安全策略。
- 不在主面板加入延迟图表、费用统计、账号、订阅或多用户房间信息。
